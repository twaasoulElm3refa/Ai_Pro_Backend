==================================================

تاريخ التحليل: 2026-09-07

جذر المشروع: C:\xampp\htdocs\Ai_Pro_Backend

ملاحظة عن المسارات:
كل مسار نسبي مذكور أدناه يبدأ من جذر المشروع أعلاه، ولذلك فهو File Path حقيقي داخل المشروع.


الخلاصة التنفيذية
=================

1) FreeAiModelShow.vue هي Landing/Details page لأداة Free AI رئيسية مخزنة في جدول
   main_free_ai_models. تحمل بيانات العرض وSEO بالـ slug، ثم تنشئ conversation وتنتقل إلى صفحة الدردشة.

2) FreeAiModelChat.vue تنفذ حاليًا:
   - تحميل conversation واحدة.
   - تحميل قائمة conversations للمستخدم والأداة نفسها.
   - إنشاء وحذف conversation.
   - تحميل execution-model catalog من خدمة خارجية عن طريق Laravel proxy.
   - اختيار execution model وحفظ snapshot منه في models_conversations.

3) FreeAiModelChat.vue لا ترسل رسائل AI حاليًا. الـ textarea وزر الإرسال يحملان disabled حرفيًا،
   ولا توجد message state أو sendMessage function أو POST chat endpoint مستعمل من الصفحة. الواجهة تعرض
   integrationPending وcomposerUnavailableHint. لذلك لا يوجد في هذا الجزء من المشروع تدفق فعلي:
   prompt -> provider -> assistant response.

4) endpoint الخارجي:
   GET /tasks/general-tools/{tool_key}/models
   ليس Laravel route داخل هذا repository. هذا المشروع يتعامل معه كخدمة خارجية على api.aiarabic.com،
   ويعرضه للواجهة عبر proxy محلي:
   GET /api/v1/model-catalogs/{source}

5) general_code وgeneral_translation ليسا سجلات Models محلية ولا routes Vue. إنهما source/tool keys
   في config/model_catalogs.php، ويربط كل واحد منهما endpoint catalog خارجيًا.

6) provider وprovider_model_id يصلان من catalog الخارجي. لكن التنفيذ الحالي يحفظ فقط
   provider_model_id مع catalog ID والاسم والمصدر. لا توجد عملية اختيار Provider أو استدعاء OpenRouter/OpenAI
   من Free AI flow لأن إرسال الرسالة نفسه غير منفذ.

7) يوجد نظام آخر منفصل اسمه General Tools في:
   resources/js/views/home/generalTools/showGeneral.vue
   resources/js/views/home/generalTools/GeneralChat.vue
   هذا النظام يقرأ sub_tools حيث main_tool_id = 8، ودردشته Local-only في ذاكرة Vue. لا يجب الخلط بينه
   وبين model catalog keys المسماة general_code/general_translation.


A. ARCHITECTURE OVERVIEW
========================

البنية الحالية تتكون من ثلاث طبقات من البيانات المنفصلة:

أ) Main Free AI Tool metadata
----------------------------

المصدر: قاعدة البيانات المحلية.

MainFreeAiModels / main_free_ai_models
    -> slug, name, description, image, SEO, is_active, sort_order
    -> translations من main_free_ai_models_translations
    -> تعرضها FreeAiModelShow.vue وFreeAiModelChat.vue كهوية الأداة الرئيسية.

مهم: الحقل conversation.model في response هو Main Free AI Tool، وليس execution model المختار.

ب) Conversation shell + selected model snapshot
-----------------------------------------------

المصدر: قاعدة البيانات المحلية.

ModelsConverstaions / models_conversations
    -> user_id, model_id, uuid, pinned/archive flags
    -> selected_model_source
    -> selected_model_catalog_id
    -> selected_provider_model_id
    -> selected_model_name

هذا الجدول لا يحتوي messages ولا parameters ولا provider مستقلًا.

ج) Execution Model Catalog
--------------------------

المصدر: HTTP service خارجي، وليس قاعدة بيانات هذا المشروع.

Vue
  -> GET /api/v1/model-catalogs/general_code أو general_translation
  -> ModelCatalogController
  -> ModelCatalogService
  -> GET https://api.aiarabic.com/tasks/general-tools/{source}/models
  -> يعاد catalog إلى Vue
  -> يتحول من snake_case إلى camelCase جزئيًا
  -> يظهر داخل FreeAiModelSelector

المشهد الكامل الموجود حاليًا:

Browser route
  -> FreeAiModelShow.vue
  -> main tool metadata من DB
  -> إنشاء models_conversations row
  -> FreeAiModelChat.vue
  -> conversation + history من DB
  -> catalog خارجي عن طريق Laravel proxy
  -> حفظ selected execution model snapshot في DB
  -> يتوقف التدفق هنا؛ لا توجد رسالة ولا AI completion.

D4. Origin/use of each important value
---------------------------------------

tool_key:
- يأتي داخل item من external endpoint.
- المصدر الفعلي المستخدم لاختيار endpoint هو conversation.catalog_source، وليس item.tool_key.
- frontend يحوله إلى toolKey لكنه لا يستخدمه في request أو selector.

provider:
- يأتي من external catalog.
- frontend يحتفظ به في normalized model.
- لا يرسله عند اختيار model ولا يخزنه models_conversations.
- لا يستخدم لاختيار provider في Free AI flow الحالي.

provider_model_id:
- يأتي من external catalog.
- يتحول إلى providerModelId.
- يستخدم كـ UI/model identity fallback.
- يرسل مع catalog_model_id عند create/update selection.
- backend يستخدمه لتأكيد أن ID وprovider model متطابقان.
- يخزن في selected_provider_model_id.

name:
- display name من catalog.
- يخزن snapshot في selected_model_name.

tier:
- يقبل frontend free/standard/advanced فقط؛ غير ذلك يصبح standard.
- يعرض في selector.
- لا يوجد filtering أو authorization بناءً عليه.

is_free:
- normalizeCatalogBoolean؛ default false.
- يعرض Free/Paid في selector.
- لا يمنع اختيار paid model.
- لا يستخدم backend في validation أو limits.

is_available:
- frontend default true إذا القيمة مفقودة.
- unavailable item يبقى ظاهرًا لكنه disabled.
- backend default true أيضًا عند فحص item مفقود الحقل.
- requested selection يرفض false.
- default selection يتجاهل false.

is_recommended:
- frontend/backend يستخدمانه لاختيار default المتاح.
- لا يمنح صلاحية خاصة.

sort_order:
- Laravel proxy لا يرتب items.
- backend defaultCatalogSelection يرتب تصاعديًا قبل fallback selection.
- frontend يرتب تصاعديًا مع stable original-index tie breaker.

capabilities:
- frontend يحتفظ بها كـ array.
- selector لا يعرضها.
- لا تستخدم في validation أو request أو provider execution.

parameters:
- لا يوجد حقل عام اسمه parameters في current model contract.
- الموجود upstream هو parameter_schema وrecommended_parameters.
- Laravel proxy يحافظ عليهما في response.
- modelCatalogNormalizer يحذفهما عند تحويل item إلى catalogModels.
- لا توجد controls لهما في FreeAiModelChat.
- لا ترسل temperature أو max_tokens أو أي parameters.

---------------------

داخل هذا repository لا يوجد filtering لقائمة catalog حسب:
- is_free
- tier
- provider
- tool_key

الموجود فقط:

--------------------------------

عند POST create conversation بلا catalog_model_id:

2. fetch catalog الخارجي.
3. sort by sort_order.
4. يبحث عن أحدث conversation لنفس user + main free tool تحمل source/selection.
5. يعيد الاختيار السابق إن كان item ما زال available ويطابق ID أو provider_model_id.
6. وإلا أول available recommended.
7. وإلا أول available.
8. وإلا null.

I. ERROR HANDLING
=================

I1. Frontend shared ApiClient
-----------------------------

resources/js/services/ApiClient.js، response interceptor lines 119-192:

- Network/no response:
  toast مشكلة اتصال، ثم Promise.reject.
- 400: warning طلب غير صحيح.
- 401:
  toast تسجيل الدخول، حذف auth_token، redirect بعد 1.5 ثانية إلى /{lang}/auth.
- 403: toast غير مسموح.
- 404: toast المورد غير موجود.
- 422:
  يقرأ response.data.errors، ويعرض كل field error.
- 429: toast محاولات كثيرة.
- 500: toast server error.
- 502/503/504: toast server unavailable.
- غير ذلك: unexpected error toast.

I2. Page-specific behavior
--------------------------

Main model missing/inactive:
- backend 404 Free AI model not found.
- ApiClient 404 toast.
- FreeAiModelShow: loadError card + Try Again.

Conversation missing/not owned/wrong slug:
- backend 404 Free AI model conversation not found.
- ApiClient toast.
- FreeAiModelChat: loadError card + Try Again.

Conversation list failure:
- ApiClient toast.
- component يمسح conversations ويعرض no conversations؛ لا توجد sidebar error state منفصلة.

Catalog source missing:
- conversation.catalog_source=null.
- لا يرسل frontend catalog HTTP request.
- catalogError=true وقائمة فارغة.

Unknown frontend source:
- getModelCatalogSource يرمي Unknown model catalog source.
- catalogError=true.

Unknown backend source:
- ModelCatalogController -> 404.

Catalog timeout/upstream 5xx/invalid JSON shape/missing items:
- ModelCatalogService يرمي بعد retries.
- ModelCatalogController -> 502
  {status:'error', message:'Model catalog is currently unavailable.', errors:null}.
- frontend catalogModels=[] وcatalogError=true.
- selector يصدر retry عند الضغط.

Explicit selection بينما catalog unavailable:
- FreeAiModelController -> 502.
- optimistic frontend selection يرجع إلى previous.

Catalog model missing:
- ID غير موجود -> 422.
- ID صحيح وprovider_model_id غير مطابق -> 422.
- is_available=false -> 422.
- رسالة field: The selected catalog model is unavailable.

Main free tool بلا catalog mapping عند explicit selection:
- 422 على catalog_model_id:
  This Free AI tool does not have a configured model catalog.

Default selection/catalog failure:
- conversation تُنشأ 200 مع selected_model=null.
- warning فقط في backend log.
- chat page تحاول proxy catalog مرة أخرى وقد تظهر catalogError.

Provider error:
- غير قابل للحدوث داخل Free AI message flow الحالي لأنه لا يوجد provider call.
- الأخطاء من external model catalog تصنف Catalog error/502، لا AI completion provider error.

Chat timeout/message validation:
- غير موجودان في Free AI flow لعدم وجود message endpoint.

K. DUPLICATION, LEGACY, AND RISKS
=================================

K1. Repeated catalog HTTP work
------------------------------

نفس catalog قد يطلب أكثر من مرة:
- عند إنشاء conversation بلا explicit model لتحديد default.
- مرة أخرى من FreeAiModelChat لعرض القائمة.
- عند كل PATCH model لتأكيد أن الاختيار صالح.

ModelCatalogService في backend لا يضيف application cache، بينما frontend cache لا يفيد طلبات backend الداخلية.

K2. Duplicated normalization/sorting
------------------------------------

- catalogBoolean موجود في PHP.
- normalizeCatalogBoolean موجود في JS.
- sort_order يستخدم في backend default selection وفي frontend display sorting.

هذا مقصود جزئيًا لأن backend لا يثق في client، لكنه يعني ضرورة إبقاء defaults متوافقة.

K3. Two different “General” systems
-----------------------------------

System 1 — Free AI catalog sources:
- config/model_catalogs.php
- ModelCatalogService
- general_chat/general_code/general_translation
- external /tasks/general-tools/.../models

System 2 — General Chat Tools UI:
- showGeneral.vue
- GeneralChat.vue
- generalChatService.js
- GeneralChatToolController
- GenrealToolRepository
- SubTools where main_tool_id=8
- local-only messages

الأسماء متشابهة لكن data models وroutes والسلوك مختلفون.

K4. Unused/legacy findings
--------------------------

- freeAiModelService.getModels() لا يملك caller داخل resources/js حاليًا.
- main_free_ai_models.main_tool_id غير مستعمل في public/admin Free AI code الحالي.
- ai_main_models ليست مصدر execution model catalog.
- providers table ليست مستخدمة في Free AI flow.
- generic conversations/messages/provider/billing flow منفصل، وليس fallback تلقائيًا.
- typo rollback في create_models_converstaions migration.

K5. Data-contract gaps
----------------------

- catalog يرسل parameter_schema/recommended_parameters/pricing لكن frontend normalizer يحذفها.
- provider موجود في frontend model لكنه لا يحفظ ولا يرسل.
- capabilities محفوظة في state لكن لا تعرض ولا تطبق.
- is_free/tier للعرض فقط؛ paid models يمكن اختيارها ولا يوجد billing في هذا module.
- is_available missing defaults to true في frontend وbackend.
- conversation titles دائمًا null؛ sidebar يبني fallback من أول 6 أحرف UUID.
- create admin slug random يجعل config mapping اليدوي عرضة للكسر/النسيان.


L. HOW TO ADD A NEW GENERAL TOOL
===============================

هذا القسم يصف الخطوات وفق architecture الحالية فقط، بدون تنفيذ.

أولًا: تحديد نوع الإضافة
------------------------

الحالة 1: Main Free AI Tool جديد يستخدم catalog موجودًا مثل general_code
------------------------------------------------------------------------

1. إنشاء row في main_free_ai_models (يدويًا أو عبر Admin CRUD)، مع name/description/slug/is_active/sort_order.
2. إنشاء translations في main_free_ai_models_translations أو ترك English/base fallback.
3. تسجيل exact generated slug في:
   config/model_catalogs.php -> free_ai_tools
   مثال منطقي: 'actual-new-slug' => 'general_code'.
4. لا يلزم source جديد في modelCatalogSources.js لأن general_code موجود أصلًا.
5. التحقق أن external general_code endpoint يعيد items صالحة.
6. إضافة Feature test يثبت mapping وإنشاء conversation والاختيار/reload.
7. إضافة Frontend test يثبت أن conversation.catalog_source يحمّل catalog الصحيح.

تنبيه:
إذا تم الإنشاء من Admin، MainFreeAiModelService يولد slug بـ random suffix. يجب قراءة slug النهائي وربطه،
لا افتراض أن slug يساوي name.

الحالة 2: Tool جديد له source/tool_key خارجي جديد
------------------------------------------------

مثال افتراضي: general_research.

في خدمة aiarabic الخارجية (repository غير متاح هنا):
1. إضافة GET /tasks/general-tools/general_research/models.
2. ضمان top-level response:
   {"tool":"general_research","items":[...]}
3. كل item يحتاج على الأقل ID ثابتًا وname وprovider_model_id وis_available وsort_order.
4. إذا ستستخدم الخصائص الحالية بالكامل، وفر tier/is_free/is_recommended/capabilities.
5. حافظ على x-internal-api-key authorization كما يتوقع هذا proxy.

في Laravel backend الحالي:
6. إضافة source في config/model_catalogs.php -> sources:
   - endpoint أو env URL.
   - requires_internal_key.
   - internal_key_config.
7. إضافة exact Free AI slug -> general_research في free_ai_tools.
8. route ModelCatalogController لا يحتاج route جديدًا؛ {source} generic.
9. ModelCatalogService لا يحتاج class جديدًا طالما response contract نفسه.

في Vue frontend:
10. إضافة general_research إلى MODEL_CATALOG_SOURCES في:
    resources/js/services/modelCatalog/modelCatalogSources.js
    endpoint: /model-catalogs/general_research.
11. لا تعدل getFreeAiCatalogSource؛ فهو generic ويثق بـ conversation.catalog_source.
12. FreeAiModelChat وFreeAiModelSelector يمكنهما عرض الـ source الجديد دون component جديد إذا نفس العقد.

في الاختبارات:
13. إضافة fixture حقيقية للـ response.
14. تمديد tests/Feature/ModelCatalogProxyTest.php:
    - URL الصحيح.
    - internal key server-only.
    - invalid upstream -> 502.
15. تمديد tests/Feature/FreeAiModelFlowTest.php:
    - exact slug mapping.
    - default selection.
    - unavailable/mismatch 422.
    - persisted selection and reload.
16. تمديد tests/Frontend/modelCatalog.test.mjs:
    - source registration.
    - normalization/sort.
    - route change race safety.

الحالة 3: المقصود إضافة أداة إلى /{lang}/general/chat
----------------------------------------------------

هذا مسار مختلف تمامًا:
1. إضافة SubTools row مرتبط بـ main_tool_id=8.
2. GeneralChatToolController/GenrealToolRepository سيعيده إذا الحقول متوافقة.
3. showGeneral.vue سيعرضه بعد normalize/filter is_active+slug.
4. GeneralChat.vue سيخزن messages في Vue فقط.
5. هذا لا يضيف general_code/general_translation catalog، ولا Free AI conversation، ولا AI provider execution.

قبل أي تنفيذ يجب حسم أي معنى هو المقصود من “General Tool”. بالنسبة للنمط المذكور في الطلب
general_code/general_translation، الحالة 1 أو 2 هي الصحيحة، وليست الحالة 3.

إضافة message execution مستقبلًا ليست جزءًا آليًا من catalog pattern
---------------------------------------------------------------

حتى بعد إضافة source جديد، النظام سيظل يختار model فقط. لتفعيل AI chat يلزم تصميم جديد غير موجود حاليًا، يشمل:
- Route POST خاص بمحادثات models_conversations.
- FormRequest/DTO لعقد prompt/messages/parameters.
- ownership validation.
- إعادة جلب/تحقق selected catalog model server-side.
- provider dispatch باستخدام provider + provider_model_id.
- parameter_schema validation وrecommended defaults.
- messages table أو relation مناسبة لـ models_conversations.
- usage/rate/free-vs-paid policy.
- response أو SSE contract.
- frontend draft/messages/loading/error/cancel/regenerate implementation.

هذه ليست “ملفات ناقصة يمكن تخمينها”، بل gap معماري حقيقي في الحالة الحالية.
